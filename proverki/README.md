# Наборы проверок

Здесь лежит всё, чем проверяется продукт: сами наборы и три запускалки. До версии 8.0 они жили
вне репозитория, во временном каталоге рабочей машины, и однажды пропали вместе с ним: полсотни
наборов, написанных с 7.2 по 8.0, восстановить было неоткуда. Поэтому теперь они здесь.

## Что нужно, чтобы прогнать

- **.NET SDK 10** (тот же, что для сборки продукта)
- **Node.js 22 и выше**
- **Playwright** с Chromium: `npm i -D playwright && npx playwright install chromium`

  Ставится он **в этом каталоге**, рядом с `package.json`, а не глобально: наборы ищут его
  обычным разрешением модулей от своего места. Каталог `node_modules` в git не лежит - так же,
  как не лежат библиотеки планшета. После получения репозитория:

  ```bash
  cd proverki && npm i && npx playwright install chromium
  ```

Наборы не привязаны к машине: путь к браузеру и рабочий каталог берутся из окружения.

| переменная | зачем | по умолчанию |
|---|---|---|
| `SK_CHROME` | путь к Chromium | пусто, Playwright берёт свой |
| `SK_RABOTA` | куда складывать данные и журналы прогонов | `<репозиторий>/.proverki` |
| `SK_TABLET_IP` | адрес подставного планшета для набора про управление | `192.0.2.2` |

## Как прогнать

Сначала собрать продукт. Сборка идёт под общим замком: два прогона, начавшие её одновременно,
писали в один `bin/Release` и получали половину чужих файлов.

```
bash proverki/build_lock.sh
```

Один набор:

```
bash proverki/run_iso_safe.sh regr_v83_pol 5601
```

Несколько разом, каждый на своём порту (на четырёх ядрах три это разумный предел, каждый набор
поднимает и службу, и браузер):

```
bash proverki/run_par.sh 5601 3 regr_v80_porogi regr_v81_kartinki_gruppy regr_v83_pol
```

Итоги одновременного прогона лягут в `$SK_RABOTA/par_<набор>.res`, полный вывод в
`$SK_RABOTA/out_<набор>.log`.

**Каждый прогон обязан идти на своём порту и со своим каталогом данных.** Иначе наборы затирают
друг другу состояние и падают не на продукте, а друг на друге. Запускалка это обеспечивает сама,
от вас нужен только неповторяющийся порт.

## Как читать итог

Набор печатает строку на каждую проверку и итог в конце:

```
PASS картинка чужого кабинета до него НЕ дошла
FAIL реклама прежнего кабинета ушла с планшета: ["/media/...","/media/..."]
ПРОВАЛОВ: 1
```

Строка провала всегда несёт замер: что именно оказалось на месте ожидаемого. Без замера строка
провала бесполезна, по ней нельзя понять, беда это или ошибка самого набора.

## Правила, выведенные из своих же ошибок

**Первым прогонам не верить.** Набор упал, значит сначала читаешь исходник и доказываешь, что
беда настоящая, и только потом правишь продукт. Обратный порядок несколько раз приводил к починке
исправного.

**Набор, написанный чтобы показать беду, после починки «падает».** Его проверки написаны так, что
проходят при наличии беды. Такой набор переписывается под правильное поведение, а не ослабляется
и не выкидывается.

**Зелёный на пустом месте хуже красного.** Проверка «ничего не сломалось» проходит и тогда, когда
проверять было нечего: пустой экран, несобравшаяся панель, ненайденный элемент. Каждая проверка
должна сначала убедиться, что предмет проверки вообще существует.

**Доступ планшета в наборе.** Не `?token=`, так планшет застревает на экране активации, а набор
меряет пустой экран и проходит на пустом месте. Правильно:

```
POST /api/admin/devices/enroll  -> {code}
POST /api/kiosk/enroll {code}   -> {deviceId, name, token}
затем в браузере: goto "/", localStorage.setItem("sk_device_token", token), reload
```

**Планшет показывает один кадр рекламы за раз.** Считать картинки на экране бессмысленно. Список,
который держит планшет, лежит в `window.__slidesForTest`.

**Кириллические имена переменных ломают оболочку:** `имя=0` и `$((имя+1))` не работают. В
сценариях оболочки имена только латиницей. В коде наборов и в текстах проверок наоборот, всё
по-русски.

**Русские буквы в теле запроса уходят экранированными**, вида `Про`. Это тот же
самый текст в записи JSON, а не поломка. Сравнивать надо разобранное тело, а не искать подстроку
в сыром.

**Спящий `sleep` в переднем плане в некоторых средах не работает.** Ждать через `curl --retry`,
через таймауты Playwright или запросами к `/healthz`.

## Что здесь лежит

Около полутора сотен наборов. Часть из них написана под версии 4.x, 5.x и 6.x и проверяет
поведение, которое продукт с тех пор умышленно изменил: такие наборы краснеют законно, и их надо
переписывать под нынешнее поведение, а не подгонять под зелёное. Разобранные примеры этого:
`e2e_v45` (ключ управления с переводом строки теперь отвергается с объяснением, а не чистится
молча) и `e2e_v45_fontsize` (кнопки размера убраны, размер задаётся числом в точках).

Самые свежие, написанные под 7.9 и 8.0:

| набор | что проверяет |
|---|---|
| `regr_v79_uvedomlenia` | уведомления оператору целиком, долгий: две выдержки сторожа |
| `regr_v80_porogi` | пороги уведомлений и разговор о приведении к границам |
| `regr_v81_kartinki_gruppy` | реклама по наборам планшетов, сроки показа, переезд планшета |
| `regr_v82_upravlenie` | управление планшетом из админки, 25 проверок через подставной FreeKiosk |
| `regr_v83_pol` | условие по тегу в другом написании, экран против редактора |
