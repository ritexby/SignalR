HELIX SignTablet v5.1

Слайды (реклама)

Реклама отправится выбранному адресату («Кому»): все / группа / конкретный планшет. Выбор здесь не зависит от вкладки «Документ». Номер на картинке - её порядок.

Документ для подписанта

Документ показывается только на один выбранный планшет (вместе с его персональными данными). Реклама (вкладка «Слайды») настраивается отдельно и может идти на все планшеты, группу или один - это независимо.

Планшетов пока нет, поэтому отправить документ некуда. Заведите планшет на вкладке «Планшеты»: там создаётся код активации, который вводится на планшете один раз. Документ можно готовить и без планшета, а также посмотреть в предпросмотре.
Подстановка данных: пишите в тексте {{ФИО}}, {{ДР}}, {{Адрес регистрации}} - при показе через API на их место подставляются значения. Можно использовать в заголовках, тексте, пунктах чекбоксов и в условиях показа. Регистр не важен: {{ПОЛ}} и {{Пол}} это один тег. Список ниже не ограничение: в запросе можно прислать поле с любым именем, и если такой тег стоит в тексте, он заполнится. Список это то, что уже согласовано и предлагается в подсказках.

Полученные подписи

Сканировать ШК/QR

Планшетов пока нет, а сканирует именно планшет своей камерой. Заведите планшет на вкладке «Планшеты».
На выбранном планшете откроется камера. Поднесите QR или штрихкод (EAN-13, EAN-8, Code-128) к окну на экране. После успешного считывания планшет покажет «Код считан», код сохранится в списке ниже, и планшет вернётся к обычному экрану.

Планшеты

Новый планшет добавляется кодом активации: сгенерируйте код, введите его на планшете один раз - он получит защищённый доступ.

Управление планшетами по локальной сети

Приложение FreeKiosk на планшете отвечает на запросы по своему адресу в локальной сети. Включите управление, и на карточке каждого планшета появится кнопка «Управление»: перезагрузка, перезапуск приложения, очистка кэша, экран, яркость, снимок экрана. Сервер и планшеты должны быть в одной сети.

Автолечение сначала перезапускает приложение на планшете, и только если планшет так и не вышел на связь, перезагружает его целиком. Перезагрузка работает при включённом режиме Device Owner на планшете. После трёх безуспешных попыток автолечение останавливается, и оператор получает уведомление, что планшет требует осмотра.

Расписание

Команды по времени для всего парка, группы или одного планшета: утром включить экраны, вечером погасить, ночью перезагрузить. Время указывается по часам сервера (-). Команды идут по локальной сети, поэтому управление выше должно быть включено, а сервер и планшеты должны быть в одной сети.

Если сервис был выключен в назначенный момент, безопасные команды (экран, яркость, громкость, возврат рекламы) выполняются с опозданием до 30 минут: иначе утром можно прийти к тёмным планшетам. Перезагрузка, перезапуск и очистка кэша не догоняются никогда, чтобы опоздавшая команда не перезагрузила парк среди рабочего дня.

Группы планшетов

Объединяйте планшеты в группы, чтобы отправлять контент сразу на группу (выбор «Кому» на вкладках «Слайды» и «Документ»).

Рабочие места

Внешний ID - ключ вашей учётной системы (например WS-204). По нему привязка «планшет ↔ место» доступна из внешнего API.

API-ключи (внешняя система)

Ключ даёт внешней системе доступ к /api/ext/*: список планшетов, статус, привязка к местам, создание кодов активации. Ключ показывается один раз при создании.

Методы API для внешних систем

Все запросы к /api/ext/* требуют заголовок X-Api-Key с ключом из вкладки «API-ключи». Базовый адрес: .

Логи ошибок и сбоев

Сюда попадают ошибки сервиса (сбои сохранения, генерации PDF, соединений) и сбои планшетов (ошибки на экране, нет доступа к камере, неудачная отправка). Записи хранятся на сервере и переживают перезапуск.

Уведомления оператору

Уведомление появляется, когда планшет пропал со связи дольше заданного времени или когда за короткий период накопились ошибки. Оно исчезает само, как только причина устранена.
